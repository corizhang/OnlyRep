## 1. 架构总览

节点体系分两个域，通过 `NodeType` 联合类型关联（编译器强制两边同步）：

| 域 | 位置 | 职责 |
|---|---|---|
| **UI 注册表** | `src/canvas/flow/nodes/` | 节点的名称/图标/描述/默认参数/配置表单（声明式，一处定义处处生效） |
| **执行引擎** | `src/canvas/pipeline/engine.ts` | 节点的实际计算逻辑（拓扑排序 + 逐类型执行分支） |

```
nodes/
├── types.ts        # NodeTypeDef / SourceKindDef / StepConfigProps 接口 + AGG_LABELS
├── controls.tsx    # 节点控件（antd 紧凑版：NSelect/NInput/NNum/NCheck/NBtn + FieldRow + NoTableHint）
├── FormulaRow.tsx  # 公式行（只读高亮展示 + ƒx 弹窗编辑）
├── index.ts        # 注册表：STEP_DEFS / SOURCE_DEFS + 派生元信息（唯一需要"注册"的地方）
├── steps/          # 处理节点定义（8 种，一个文件一种）
│   ├── pickRows.tsx  filter.tsx  sortTopN.tsx  groupAgg.tsx
│   ├── derive.tsx    diff.tsx     union.tsx      scalarOut.tsx  formula.tsx
└── sources/        # 数据源定义（4 种 kind）
    ├── import.tsx  manual.tsx  form.tsx  constant.tsx
```

**注册表派生出的元信息**（定义一次，自动分发）：

| 导出 | 消费方 |
|---|---|
| `NODE_TYPE_LABELS` | 节点头部徽标、详情抽屉标题 |
| `STEP_TYPES` | 选中节点的「添加下游」浮层、FlowSheet 菜单 |
| `NODE_TYPE_META` / `SOURCE_KIND_META` | 左侧节点库卡片 |
| `defaultParams(type)` | 创建节点时的初始参数 |
| `Config` 组件 | **节点内嵌配置**（FlowNodeCard）与**右侧详情抽屉**（NodeFields）复用同一个 |

## 2. 消费方文件职责

| 文件 | 职责 |
|---|---|
| `FlowNodeCard.tsx` | 节点卡片外壳：头部（徽标/改名/拖拽）、查注册表渲染配置区、底部结果预览、antd 主题嵌套、高度上报 |
| `FlowSheet.tsx` | 画布：平移缩放、布局连线、拖放入库、选中浮动工具条（添加下游/启停/删除）、连线端口 |
| `NodeFields.tsx` | 右侧详情抽屉配置区（复用注册表 Config + 显示名字段） |
| `nodeOps.ts` | 创建节点/数据源的纯函数（名称去重、默认参数） |
| `layout.ts` | 分层 DAG 自动布局（支持可变高度节点，DOM 实测高度驱动） |
| `nodeTheme.ts` | 节点域双主题 token（--nb-* CSS 变量，dark/light 两套调色板） |

## 3. 如何新增一个处理节点（以「去重 unique」为例）

### 第 1 步：类型声明（`src/canvas/types.ts`）

```ts
export type NodeType = 'source' | 'pickRows' | 'filter' | ... | 'unique';  // 加成员
```

### 第 2 步：引擎执行分支（`src/canvas/pipeline/engine.ts`）

在 `runNode` 的 switch 中加 `case 'unique'`：读取上游表格 → 按列去重 → 返回 `{ kind: 'table', table }`。

### 第 3 步：节点定义（新建 `src/canvas/flow/nodes/steps/unique.tsx`）

```tsx
import { FieldRow, NSelect } from '../controls';
import type { NodeTypeDef } from '../types';

export const uniqueDef: NodeTypeDef = {
  type: 'unique',
  label: '去重',                    // 徽标/库名称/初始节点名
  icon: '⚙',                        // 节点库图标（单字符）
  desc: '按列去除重复行',            // 节点库卡片描述
  hint: '按列去除重复行',            // 添加下游按钮提示
  needsTableInput: true,            // 必须接表格类上游（公式类节点为 false）
  defaultParams: () => ({ col: '' }),
  Config: ({ node, cols, setParam }) => (
    <FieldRow label="列">
      <NSelect value={String(node.params.col ?? '')} placeholder="选择列" options={cols} onChange={(v) => setParam({ col: v })} />
    </FieldRow>
  ),
};
```

### 第 4 步：注册（`src/canvas/flow/nodes/index.ts`）

```ts
import { uniqueDef } from './steps/unique';
const STEP_DEF_LIST: NodeTypeDef[] = [pickRowsDef, ..., uniqueDef];  // 加一行
```

**完成**。节点库、「添加下游」浮层、头部徽标、默认参数、节点内配置、右侧抽屉配置全部自动出现，无需再改。

### Config 组件可用的入参（`StepConfigProps`）

| 字段 | 说明 |
|---|---|
| `node` | 节点本体（`node.params` 读参数） |
| `cols` | 上游表格列 `[{value, label}]`（无表格上游时为 `[]`） |
| `rowColumns` | 行公式可用的上游列（派生列用） |
| `rowSample` | 上游第一行（行公式实时预览用） |
| `setParam(patch)` | 写回 `node.params` |

> 框架行为：`needsTableInput: true` 且未接表格上游时，配置区自动替换为 `NoTableHint` 提示，Config 不会被渲染（无需自己判空）。

## 4. 如何新增数据源类型（以「API 数据源」为例）

1. `types.ts`：`DataSource` 联合加 `ApiDataSource`，`kind: 'api'`；
2. 引擎 `runSource` 加分支（产出表格或标量）；
3. 新建 `nodes/sources/api.tsx`，实现 `SourceKindDef`（label/desc/icon/Config），Config 接收 `{ srcDef, srcRt }`；
4. `nodeOps.ts` 的 `createSourceOfKind` 加创建分支（初始 name/字段）；
5. `nodes/index.ts` 的 `SOURCE_DEF_LIST` 注册一行。

## 5. 关键机制速查

- **双主题**：节点域颜色一律用 `var(--nb-*)`（定义见 `nodeTheme.ts`），组件禁止写死色值；controls.tsx 里的控件带浅色兜底（抽屉上下文无 --nb-* 注入）。
- **antd 主题**：FlowNodeCard 内嵌 `ConfigProvider`（dark→darkAlgorithm / light→默认），抽屉里是 App 全局浅色——同一套 NSelect 等组件两处自动适配。
- **拖拽规则**：节点头部按住拖动；`onShellDown` 对 `input/.ant-select/.ant-btn/.no-drag` 等区域 stopPropagation，新增自定义交互区时按需加 `no-drag` 类或扩充排除清单。
- **高度与连线**：节点高度由 ResizeObserver 实测上报（`onHeight`），布局/连线锚点按实际高度计算——配置区任意增高都安全。
- **结果预览**：`DarkPreview` 按输出 kind 通用渲染（表格前 6 行/数值/参数/错误），新节点类型一般无需改；`scalarOut`/`formula` 会自动追加「变量名」chip。
- **验证约定**：`npx tsc --noEmit` → `npx vitest run`（TMP 指到 .tmp-vt2）→ `npx vite build`（单文件门限 6MB）→ Playwright 截图（`.shots/verify*.cjs`）。提交前四步全过。

## 7. 内置节点速查

| 节点 | 说明 | 典型链路 |
|---|---|---|
| 取行 pickRows | 最新日期 / 前 N / 后 N / 全部 | 数据源 → 取行 → 取数 |
| 筛选 filter | 按列值过滤行 | — |
| 排序 sortTopN | 升降序 + 截取前 N（可按日期） | 排行榜 |
| 分组聚合 groupAgg | 按维度汇总（求和/平均/计数/最大/最小） | 渠道汇总 |
| 派生列 derive | 行内公式新增一列 | 完成率列 |
| **差分 diff** | **较上日增加：数值列按日期逐行「本行-上一行」**；首日留空；可选**分组列**（多快照合并后按分行等维度分组差分） | **列场景**：直接出表；**数字场景**：差分 → 取最新日 → 取数；**跨文件较上日**：合并 → 差分(分组列) → 筛选当日 |
| **合并 union** | **双输入**：两张表按列并集纵向堆叠，缺列补空（「2 入」徽标即就绪） | T ∪ T-1 两份日报快照合并 |
| 取数 scalarOut | 对列聚合出一个数值（写入变量环境） | KPI/文案引用 |
| 计算字段 formula | 公式产出新变量（无需表格上游） | 完成率/剩余天数 |
